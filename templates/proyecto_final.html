Cierre del curso

Proyecto Final

El broche de oro del curso: tu oportunidad de salir con todo lo que aprendiste de SQL y crear tu propia base de datos. Te pedimos que construyas algo que te importe, que resuelva un problema de verdad, que impacte positivamente a otros o que cambie el mundo. Esfuerzate por crear algo de lo que te sientas orgulloso.

Antes de empezar: leé bien todo este enunciado. Acá tu diseñas la base de datos desde cero: las tablas, las relaciones, los índices y las consultas. 🌟 — Es el momento de demostrar todo lo que sabes.

¿Solo o en equipo?

Como desarrollar software rara vez es trabajo de uno solo, van a trabajar en el grupo que estudiantes que el profesor conforme. Cada integrante del grupo debe contribuir por igual al diseño y la implementación.

Sobre qué se va a trabajar?

Para arrancar, acá van a trabajar sobre el proyecto escogido por cada grupo

Cómo empezar

Para darte algo de estructura, Harvard te entrega tres archivos plantilla: DESIGN.md, schema.sql y queries.sql. Empezá por descargarlos y leer las secciones de abajo.

Qué hay que entregar

Tu proyecto final se compone de tres archivos:

DESIGN.md

Documento de diseño riguroso que describe el propósito, el alcance, las entidades, las relaciones, las optimizaciones y las limitaciones de tu base de datos.

  • Diagrama entidad-relación
  • Video de máximo 5 minutos

schema.sql

Conjunto de sentencias CREATE TABLE, CREATE INDEX, etc. que componen el esquema de tu base de datos, anotadas con comentarios SQL.

queries.sql

Conjunto de consultas SELECT, INSERT, UPDATE, DELETE, etc. que los usuarios normalmente ejecutarían sobre tu base de datos, anotadas con comentarios.

1. DESIGN.md — El documento de diseño

Escribe sobre el propósito, el alcance, las entidades, las relaciones, las optimizaciones y las limitaciones de tu base de datos. Escribe para un público técnico que haya cursado algo similar a lo que vimos en base de datos. El objetivo es hacer visible tu proceso de pensamiento.

Debe incluir texto en todas las secciones que prescribe la plantilla, tener como mínimo varios párrafos de largo y explicar por qué tomaste ciertas decisiones de diseño. Un DESIGN.md de unas 1000 palabras suele ser suficiente. Si no llegás a ese umbral, probablemente tu proyecto no es lo suficientemente completo.

Diagrama entidad-relación

Tu DESIGN.md debe incluir un diagrama entidad-relación de tu base de datos. Podés crearlo como prefieras:

  • Si sos de lápiz y papel: dibujá, tomale foto y subila.
  • Si sos más digital: usá Mermaid.js (el live editor). Mirá la documentación de diagramas ER.
  • O cualquier otro software que te sirva para dibujar las formas que quieras.

Para insertar la imagen en tu DESIGN.md:

Video de presentación

Creá un video corto (máximo 5 minutos) en el que presentes tu proyecto al mundo: con diapositivas, capturas de pantalla, voz en off y/o acción en vivo. Tu video debe empezar con una sección que muestre:

  • el título de tu proyecto
  • nombres de los integrantes del equipo
  • El repo de git en dónde quedó el proyecto
  • Tu institucion educativa
  • la fecha en que grabaste el video

Sube el video a YouTube y anotá la URL. Podés marcarlo como "no listado", pero no como "privado".

2. schema.sql — El esquema

Tu archivo schema.sql debe incluir las sentencias SQL que definen el esquema de tu base de datos, anotadas con comentarios SQL breves. Acordate que un comentario en SQL empieza con --: 

-- Este es un comentario SQL

Probablemente contenga sentencias CREATE TABLE, CREATE INDEX y CREATE VIEW.

3. queries.sql — Las consultas

Tu archivo queries.sql debe incluir las consultas que los usuarios normalmente ejecutarían sobre tu base de datos, anotadas con comentarios breves. Probablemente contenga SELECT, INSERT, UPDATE y DELETE.
